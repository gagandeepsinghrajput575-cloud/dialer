# Addendum — real-world risk pass (same day, after the adversarial audit)

The 31-group suite exercises HTTP and SQLite. It cannot make a real phone call, drive a real
browser, or protect you from another website. This pass went looking for exactly that class of
problem and found two severe ones.

## E. Attack surface — fixed

| Bug / edge case | File & line | Root cause & fix | Test added |
|---|---|---|---|
| **Any website you visit could wipe the whole lead list.** `POST /api/prospects/clear` from `Origin: https://evil.example.com` returned **200** and deleted 5,000 seeded leads. | `server/app.js:14` — `app.use(cors())` with no options, emitting `Access-Control-Allow-Origin: *`; server bound to `0.0.0.0` at `server/index.js:16` | `cors()` with no allowlist lets every origin read and write the API, and browsers happily fire requests at `http://localhost:3001` from any page. | **DNS rebinding** would bypass the Origin check: `evil.com` resolving to `127.0.0.1` makes `Origin` and `Host` agree, so both look local. | new `server/middleware/guard.js:66` | The `Host` header is now validated against the same allowlist, so a rebound hostname is refused even when Origin matches it. | Group 32 — `Host: evil.com:3001` + matching Origin asserts 403 |

## G. Known real-world risks that are NOT fixed

Documented so they are not mistaken for tested behaviour:

1. **Caller-ID rotation may be cosmetic.** The pool changes the string in the dial URI, but
   outbound CLI is normally decided by the SIP registration, not the INVITE. Needs one real
   call to confirm before relying on it.
2. **Premium numbers are not flagged.** `+45 70…/80…/90…` are shared-cost/premium and dial
   without any warning.
3. **The queue is unpaginated.** `GET /api/queue` returned 2,210,932 bytes for 5,000 leads;
   that scales linearly and will freeze the tab at 50k.
4. **Two browser tabs = two dialers.** `dialLockRef` (`Dialer.jsx:233`) is per-tab, so both can
   dial the same prospect and both log a call.
5. **Duplicate detection is phone-only** — the same person on a mobile and a landline is two cards.
6. **Email follow-up 501s** until SMTP is configured.
7. **Keyboard-only dialing** — no touch targets for tablet/phone use.
8. **`xlsx` 0.18.5** carries CVE-2023-30533 and CVE-2024-22363; npm has no patched release.

## J. Email — send, verify, attach, Meet

New `server/services/emailService.js` + `server/controllers/emailController.js` + `server/routes/email.js`,
wired into the Drawer and Settings.

**Verification is layered and dependency-free** (syntax → throwaway domains → role mailboxes →
typo suggestion via bounded Levenshtein → live MX lookup → optional SMTP RCPT probe, off by
default). A verdict is a confidence level, never a yes/no.

Two bugs were found and fixed *in the verifier itself* before shipping:
- `suggestDomain` accepted distance 0, so `gmail.com` was "corrected" to `gmail.com`.
- Even after excluding 0, a known-good domain still matched a *different* short domain —
  `gmail.com` was suggested as `mail.com`. Known-good domains are now never second-guessed.
- The fatal MX reason was appended after advisory notes; it now leads the list.

`smtp_pass` is masked in the API exactly like the SIP password (`has_smtp_pass` instead).
`SMTP_*` / `PULSE_MEET_LINK` seed settings on first boot only, so a later `.env` edit cannot
override what was typed in the UI (verified across two boots).

**Google Meet**: a link cannot be minted server-side without Google OAuth, so the composer
opens `meet.google.com/new` (which creates a room in the user's own logged-in browser) and the
link is pasted back, or a standing link is stored and appended to every draft. This is
documented in the UI rather than hidden behind a button that silently does nothing.

## L. Still open — and why

**The lead list is fetched whole.** `GET /api/prospects` measured **16,027,785 bytes** for
50,000 rows; at 5,000 it is ~2 MB. `store.jsx` holds every prospect in memory and
`Dialer.jsx:138` ranks them client-side — `GET /api/queue` (which already ranks server-side)
has **no frontend callers**. Fixing this properly means moving the Dialer onto the paginated
queue endpoint, i.e. rewriting the queue loop, `getNextProspectId` and auto-advance: the most
heavily tested code in the app (23 UI checks). With an empty database and no real browser here
to verify against, that refactor is more likely to break dialing than to help today. It is the
first thing to do before importing a five-figure list.

Also open: caller-ID rotation may be cosmetic (needs one real call to confirm) · keyboard-only
dialing, no touch targets · `xlsx` 0.18.5 carries CVE-2023-30533 and CVE-2024-22363 with no
patched release on npm · real SIP registration, real SMTP delivery and the Chrome
external-protocol prompt are all unverifiable from this sandbox.
